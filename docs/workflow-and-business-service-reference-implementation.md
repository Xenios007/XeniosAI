# ARCH-020-06 Workflow and Business Service Reference

`WorkflowAndBusinessServiceReferenceDescriptor` exposes immutable metadata for the reference bounded services, service ownership responsibilities, command fields and provider validations, query characteristics, event fields, reservation workflow steps, workflow state elements, idempotency examples, concurrency controls, failure scenarios, reconciliation-checked records, observability trace-correlation points, acceptance criteria, and architectural rules.

Profile validation requires services to own and protect their repositories, duplicate commands to not duplicate material effects, a cross-service workflow to recover after worker restart, partial failure to produce visible state and compensation, events to correspond to committed facts, tenant context to remain present in every boundary, business state changes to be deterministic service commands, workflows to coordinate without owning domain truth, local transactions and reliable events to replace shared transactions, and reconciliation to be a first-class recovery control. It rejects workflow state duplicating authoritative service records, a distributed shared-database transaction being used, notification failure automatically reversing a booking, reconciliation differences silently overwriting data, and read models acting as alternative authorities.

The module demonstrates deterministic business services, commands, queries, events, workflows, transaction boundaries, idempotency, concurrency, and reconciliation — turning business rules into independently owned services and durable workflows with explicit consistency, failure, and recovery semantics.
