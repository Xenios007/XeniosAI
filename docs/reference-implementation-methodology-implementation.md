# ARCH-020-02 Reference Implementation Methodology

`ReferenceImplementationMethodologyDescriptor` exposes immutable metadata for method principles, scenario selection criteria, scenario definition fields, architecture traceability mappings (reference artifact to architecture evidence), conformance profile elements, implementation lifecycle steps, evidence package items, variation point categories, divergence classifications, review gate areas, maintenance monitoring areas, retirement elements, and architectural rules.

Profile validation requires traceability to be bidirectional between architecture and examples, variation-point substitution to retain contracts/invariants/tests/quality outcomes, a new scenario to move from proposal to release through repeatable gates/evidence/ownership/variation rules/lifecycle, conformance to be profile based and evidence backed, traceability to be mandatory for material artifacts, variation to be explicit and test preserving, maintenance and retirement to be part of reference scope, and architecture changes to follow governance rather than example drift. It rejects scenarios duplicating one another without a meaningful variant, unclassified divergence being presented as conformant, and a stale reference being silently presented as current instead of marked unsupported.

The module makes reference implementations reproducible architecture evidence rather than informal sample code: scenarios are selected by business relevance and risk, defined completely, traced bidirectionally to architecture, bound to a risk-appropriate conformance profile, carried through a repeatable proposal-to-release lifecycle with a full evidence package, and explicitly governed through variation, divergence classification, review gates, maintenance, and retirement.
