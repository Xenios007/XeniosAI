# ARCH-020-04 Multi-Property Enterprise Reference

`MultiPropertyEnterpriseReferenceDescriptor` exposes immutable metadata for the enterprise scenario's actors, hierarchy levels, enterprise capabilities, access-model dimensions, configuration-precedence levels, data-isolation controls, knowledge/memory scopes, cross-property workflow steps, integration-topology dimensions, resource-governance scopes, deployment variants, operations-visibility dimensions, failure scenarios, acceptance criteria, and architectural rules.

Profile validation requires tenant and property contexts to survive all sync and async boundaries, provider services to reject cross-tenant resources, tenant configuration to be unable to change platform policy floors, workload contention to remain bounded, incidents to identify affected tenant scope, tenant restore and migration to preserve other tenants, cross-property access to be an explicit portfolio grant, and isolation topology to be replaceable behind stable tenant contracts. It rejects portfolio hierarchy automatically granting data access, lower scopes weakening mandatory controls, one failing property integration consuming another property's retry budget, tenant-specific restore overwriting another tenant, and shared services skipping provider-side tenant validation.

The module demonstrates how the single-property vertical slice (`SinglePropertyHospitalityReferenceDescriptor`) scales to portfolios and many tenants — evolving the same domain semantics rather than forking the single-property product, while preserving ownership, authorization, configuration, resource, data, and operational boundaries across tenants and properties.
