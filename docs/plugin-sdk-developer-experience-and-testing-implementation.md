# ARCH-019-07 Plugin SDK, Developer Experience, and Testing

`PluginSdkDeveloperExperienceAndTestingDescriptor` exposes immutable metadata for developer experience principles, Plugin SDK scope items, SDK layers, SDK prohibited behaviors, language SDK release declarations, SDK generation properties, developer portal capabilities, extension-point catalog fields, project template elements, local sandbox emulations, test tenant requirements, unit/contract/integration testing coverage, security testing requirements, failure testing scenarios, compatibility testing dimensions, uninstall testing requirements, conformance profile result fields, the developer workflow, packaging and publishing tooling capabilities, documentation requirements, reference extension examples, developer observability elements, SDK lifecycle fields, and architectural rules.

Profile validation requires the paved road to remain faster than private integration shortcuts, SDKs to trace to canonical contracts without hidden authority, local development to mirror hosted capability and tenant rules, every package to pass applicable multi-tenant, security, failure, and compatibility tests, build artifacts to carry exact digests, inventories, and provenance, publishing to separate package submission from tenant installation, documentation to cover operation, support, update, and uninstall, developer feedback to have accountable owners and a visible lifecycle, generated code to stay separated from handwritten code and regeneration compatible, manual edits to generated files to be prohibited or isolated, undocumented internal endpoints to never appear as supported extension points, templates to default to minimal capability and deny-by-default network access, publishers to be unable to self-declare certification above the verified result, publishing tools to never accept production tenant credentials or create runtime grants, failed review to return actionable remediation guidance, and CLI history, build logs, examples, and diagnostics to redact secrets. It rejects development tools using production tenant credentials, sandboxes carrying production credentials or network paths by default, treating single-tenant success as isolation proof, bundling credentials in tools or templates, language convenience weakening capability or tenant context, copying production data into sandboxes without approved controls, developers querying other publishers' private evidence, extension-point owners creating private contract exceptions, exempting old SDKs from supported-version certification, requiring identical API shape across languages, and SDK releases omitting support window or migration guidance.

The module makes safe extension development the standard path: canonical contracts, secure templates, local sandboxes with no ambient production authority, mandatory multi-tenant negative testing, deterministic and inspectable packaging with provenance, separated publisher/installer/runtime identities, and mandatory uninstall and failure-path examples give publishers a productive workflow while preserving host enforcement and domain authority.
