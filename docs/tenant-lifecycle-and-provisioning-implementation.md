# ARCH-018-03 Tenant Lifecycle and Provisioning

`TenantLifecycleProvisioningDescriptor` exposes immutable metadata for lifecycle principles, lifecycle states, transition contract fields, tenant request inputs, assessment areas, approval elements, provisioning coordinator steps, provisioning domains, desired-state manifest properties, idempotency and concurrency distinctions, failure and compensation responses, validation readiness checks, activation preconditions, active-state changes, restriction examples, suspension exceptions, reactivation checks, tenant migration steps, offboarding plan elements, data export requirements, retention classifications, retirement conditions, reconciliation findings, lifecycle events, lifecycle roles, evidence questions, service objectives, and architectural rules.

Profile validation requires authoritative effective-dated state, command-based transitions with evidence and an accountable owner, idempotent resumable provisioning, validation-gated activation, visible and recoverable partial failure, policy-driven suspension, identity-preserving migration, derivative-covering offboarding, retention that can outlive access, provider-owned resource lifecycle, rejection of conflicting or stale commands, idempotent command replay, a versioned comparable desired-state manifest, and reconciliation-driven remediation. It rejects reused retired identifiers, resource creation alone proving activation, unconditional reactivation, invoice status modifying authorization, assumed exact-state compensation, migration changing tenant identity, export containing platform secrets, unrepresented manual resources being treated as expected, and provider work requiring a distributed lock.

The module coordinates independently owned providers through versioned desired state and evidence rather than owning domain resource lifecycles directly.
