# ARCH-020-01 Reference Implementation Overview

`ReferenceImplementationOverviewDescriptor` exposes immutable metadata for reference mission questions, the portfolio's three reference tiers (single-property baseline, enterprise baseline, cross-cutting pattern references), reference stakeholder needs, reference target-state characteristics, reference quality attributes, the adoption-path steps, reference success measures, per-reference declaration fields, and architectural rules.

Profile validation requires reference implementations to make XeniosAI architecture observable through realistic, inspectable, and reproducible evidence; the portfolio to begin with Casa Lluvia and expand to enterprise operation; reference value to be measured through demonstrated outcomes and conformance; cross-cutting requirements to appear in every complete scenario; consumers to reuse patterns rather than undocumented implementation accidents; reference maintenance to have named ownership and lifecycle; and every reference to declare purpose, classification, architecture coverage, actors, acceptance criteria, limitations, data policy, tests, operations, and a maintenance owner. It rejects consumers copying the entire solution instead of selecting reusable patterns, the portfolio being left unversioned or unmaintained, reference limitations being left undisclosed, and reference retirement occurring without governed feedback.

The module opens ARCH-020 Reference Implementations: a controlled bridge between XeniosAI architecture and implementation that starts with a real single-property operating model, demonstrates enterprise growth, and supplies reusable, testable patterns — traceable, executable, secure by default, multi-tenant testable, and governed through feedback and retirement — across the platform.
