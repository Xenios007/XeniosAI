# ARCH-019-05 Capability Security and Isolation

`CapabilitySecurityIsolationDescriptor` exposes immutable metadata for security principles, threat model items, capability grant fields, grant derivation layers, capability granularity examples, runtime identity fields, tenant isolation dimensions, host isolation classes, host security controls, provider enforcement checks, data access prohibitions, extension storage policy fields, secret mediation controls, network security controls, inbound connectivity controls, event security fields, workflow/agent security prohibitions, UI extension security controls, MCP security verification items, supply-chain admission checks, resource containment limits, failure containment controls, revocation targets, incident response steps, security evidence types, security testing areas, and architectural rules.

Profile validation requires untrusted-by-default extensions, explicitly enforceable capability, mandatory tenant/property scope, host-and-provider defense in depth, deny-by-default egress, bounded data use, installation-scoped execution and storage, non-expanding delegation, rapidly revocable security state, leak-free complete evidence, non-broadening grant-derivation layers, host validation that never substitutes for provider authorization, purpose-minimized responses, revalidated redirects, grant-filtered MCP tool discovery, advisory-driven denial of previously approved packages, and material treatment of cross-tenant exposure. It rejects ambient credentials or database access, host-policy modification or neighbor inspection, publisher storage access without a processor relationship, arbitrary listener exposure, forged event tenant scope, policy-altering MCP server descriptions, extension failure inside authoritative transactions, and UI extensions rendering platform authentication prompts.

The module assumes extensions can be compromised or malicious and limits what any package can reach, retain, transfer, or consume through explicit grants, trusted tenant context, isolated hosts, provider-side authorization, mediated secrets, deny-by-default networks, bounded storage/resources, rapid revocation, and adversarial testing.
