# ARCH-019-06 Runtime Hosts and Extension Points

`RuntimeHostsExtensionPointsDescriptor` exposes immutable metadata for runtime principles, host responsibilities and boundaries, host types, runtime admission checks, invocation context fields, extension-point contract fields, idempotency scope, API/event/workflow extension-point validations and elements, agent tool contract fields and inherited agent requirements, knowledge and memory extension-point contracts, UI extension-point controls, MCP runtime mediation, connector runtime capabilities, result validation checks, failure classifications, health evaluation factors, recovery restoration elements and exercise types, observability telemetry fields, usage metering dimensions, and architectural rules.

Profile validation requires hosts to execute only verified active digests, complete-context invocation binding, owned (not-hook) extension points, provider-authoritative domain access, host-mediated sensitive interfaces, cancelable bounded execution, out-of-transaction failure by default, revalidated async tenant scope, untrusted-until-validated results, tenant-safe evidence emission, stable admission-failure results, immutable trusted context fields, non-indefinite grant use, host-validated tool invocations, coordinated agent/package updates, cross-checked inbound tenant claims, and safety-preserving metering. It rejects fail-open authorization/security/payment controls, shared-database-transaction participation, workflow-evidence erasure on package removal, silent knowledge promotion, global memory or credential storage by extensions, UI overwriting of security chrome, unrestricted MCP tool registration, cross-tenant retry-budget consumption, direct storage credentials, internal-endpoint access, and blind non-idempotent recovery restarts.

The module turns declarative extension intent and approved installation grants into bounded execution — verifying exact packages, establishing tenant context, mediating capabilities, isolating resources, validating results, metering use, containing failure, and preserving evidence — so extensibility remains outside service internals and authoritative domain boundaries.
